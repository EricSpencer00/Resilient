# Machine arithmetic proof profile

`vm-i64-wrap-v1` describes the signed 64-bit integer semantics of the bytecode VM. It does not qualify the JIT, native/LLVM code generation, embedded targets, or a deployed application. A contract JSON report records the selected semantic profile; that field alone grants no implementation proof credit. Only a clause with `basis: implementation` and `verdict: pass` has that credit, conditional on its declared preconditions.

The profile admits integer parameters and return annotations spelled `int`, `Int`, `Int64`, `i64`, or `long`, with the effective `RESILIENT_OVERFLOW_MODE` set to Wrap (including its default). Addition, subtraction, multiplication and negation wrap modulo 2^64; comparisons are signed. Signed division truncates toward zero. MIN/-1 returns MIN, and MIN%-1 returns zero. Division and remainder by zero are errors, not unconstrained SMT values.

Implementation verdicts, diagnostic queries and accepted implementation certificates use the same BV64 formula. The formula includes expression-definedness obligations as well as the postcondition, with evaluation of preconditions before their truth is assumed, branch conditions before selecting a path, and returned expressions under the selected path. Every precondition must translate; none is silently dropped. Raw SAT sessions are counterexample diagnostics, never accepted proof certificates.

Every referenced executable name must resolve to a declared integer parameter. `result` is special only in the postcondition, unless also explicitly declared as an input parameter. Globals, conversions, narrower/unsigned types, calls, shifts, saturating/trapping arithmetic, and unmodeled body statements receive no implementation credit. The supported pure scalar body shapes are those of the contract body model. Expressions are limited to 32,768 nodes and depth 128; queries admit at most 128 axioms and path sets at most 128 paths. Solver checks have a maximum five-second timeout and unknown results do not grant credit.

Definedness currently treats both operands of Boolean expressions conservatively. It can withhold credit for a safe short-circuit expression whose unreachable operand would fault; it never uses that operand's SMT totalization to certify a fault. This restriction is not positive short-circuit coverage.

Declared clause-only checks retain their mathematical-integer interpretation. Arithmetic clause-only results cannot authorize runtime precondition-check removal. Reports requested for a failed typecheck retain diagnostics, explicitly mark `diagnostic_only`/failed typecheck, remove accepted SMT certificates, and do not grant passing clause credit. Accepted signed proof directories are emitted only after successful strict typechecking. Reports requested with typechecking disabled or a JIT execution request are diagnostic only.

The hosted qualification workflow records each requirement independently against a pinned production baseline and candidate, plus direct `--vm` execution at the overflow/division boundaries. It retains exact sources, compiler/source/solver identities, raw SAT/UNSAT sessions, evidence manifests, and signatures over raw-query records. These signatures establish retained-byte integrity and producer identity; they do not establish correctness of translation or external safety acceptance.
