# E0023 — Integer literal overflow
{: .no_toc }

An integer literal is outside Resilient's signed 64-bit (`i64`) range.
Decimal, hexadecimal, octal, and binary literals are all checked by the
lexer before the program is evaluated.
{: .fs-5 .fw-300 }

---

## What triggers it

The lexer emits E0023 when an integer literal is greater than
`9223372036854775807`, or otherwise cannot be represented as an `i64`.
The same code applies to radix-prefixed forms such as `0x...`, `0o...`,
and `0b...`.

## Minimal example

~~~resilient
let decimal = 9223372036854775808;
let hexadecimal = 0xffffffffffffffff;
~~~

With `RESILIENT_RICH_DIAG=1`, the diagnostic includes the stable code:

~~~text
<input>:1:15: error: [E0023] integer literal `9223372036854775808` overflows i64 (max 9223372036854775807)
~~~

## Fix

Keep the literal within the signed 64-bit range, split the value into
smaller checked operations, or represent it as a string/byte sequence when
it is an identifier or encoded value rather than an integer computation.

## Source

Emitted by the decimal and radix integer scanners in
`resilient/src/lib.rs`, and by the optional logos lexer in
`resilient/src/lexer_logos.rs`. The E0023 tag is shown when
`RESILIENT_RICH_DIAG=1`; default output remains unchanged.
