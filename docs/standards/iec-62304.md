# Resilient and IEC 62304

This repository does not establish IEC 62304 compliance or validation of Resilient
for a medical-device manufacturer's intended use.

## Establish the lifecycle scope

The manufacturer determines software safety classification, applicable lifecycle
activities, risk controls and tool validation under its quality management system.
Compiler checks do not establish that Class A requirements are exceeded, nor does
software class alone decide whether a tool has been adequately validated.

Distinguish development tools from software delivered in the device. An open-source
compiler is not automatically SOUP in the device software architecture. Assess
runtime and other delivered components for SOUP applicability and retain their
version, provenance, known anomalies and risk evaluation.

## Software evidence

Trace software requirements and risk controls to unit verification, integration
testing and system testing. Validate the selected compiler/backend configuration
and retain test results, anomaly dispositions and release records. Apply change
management, maintenance and problem-resolution processes. Device-level validation
and regulatory acceptance remain separate from contract checking.

## Evidence boundaries

An implementation-backed contract result applies only to the modeled semantics,
assumptions and supported subset. Check each certificate's `basis`: a
`clause-only` result is not evidence that the implementation satisfies the
postcondition. An `unknown`, unsupported or timed-out obligation is unresolved.

Replaying SMT-LIB2 checks the emitted formula. It does not independently validate
requirements, source-to-formula translation, compiler lowering, runtime behavior
or target hardware. Hashes and signatures support integrity, not correctness.
Runtime checks contribute evidence only when their presence and behavior have
been verified for the selected execution path.

## Preparation package

Use the [qualification evidence intake](../qualification-readiness) to record
intended use, a fixed toolchain baseline, requirement-to-test traceability,
reviewed evidence and unresolved gaps. Its checker reports inventory completeness;
it does not certify the compiler or approve a product.

## Reference basis

[IEC 62304:2006/AMD1:2015](https://webstore.iec.ch/en/publication/22790). Use the licensed standard and project assessment basis for exact objectives.
