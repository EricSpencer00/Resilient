# Resilient and IEC 61508

Resilient has no established IEC 61508 qualification or systematic capability
claim. Select and record the edition applicable to the assessment; this guide
uses IEC 61508-3:2010 as its reference basis.

## Define support-tool use

Document the target SIL, safety functions, software lifecycle, support-tool
classification and potential failure effects. Select and justify the required
combination of methods and tool confidence measures with the assessor.

Runtime contracts alone are not sufficient verification evidence for SIL 1/2.
Likewise, do not treat static proofs as universally mandatory for SIL 3/4 or
interpret a recommended technique as an unconditional requirement. The accepted
methods depend on the applicable objectives and project safety argument.

## Software evidence

Retain safety requirements, architecture and implementation traceability,
verification and validation results, target timing/resource tests, tool assessment,
configuration management and change impact. Review the independence appropriate
to the safety lifecycle. Hardware reliability analysis and overall functional
safety assessment remain system-level responsibilities.

## Evidence boundaries

An implementation-backed contract result applies only to the modeled semantics,
assumptions and supported subset. Check each certificate's `basis`: a
`clause-only` result is not evidence that the implementation satisfies the
postcondition. An `unknown`, unsupported or timed-out obligation is unresolved.

Replaying SMT-LIB2 checks the emitted formula. It does not independently validate
requirements, source-to-formula translation, compiler lowering, runtime behavior
or target hardware. Hashes and signatures support integrity, not correctness.
Runtime checks contribute evidence only when their presence and behavior have
been verified for the selected execution path.

## Preparation package

Use the [qualification evidence intake](../qualification-readiness) to record
intended use, a fixed toolchain baseline, requirement-to-test traceability,
reviewed evidence and unresolved gaps. Its checker reports inventory completeness;
it does not certify the compiler or approve a product.

## Reference basis

[IEC 61508-3:2010](https://webstore.iec.ch/en/publication/5517). Use the licensed standard and project assessment basis for exact objectives.
